# Spec 0.1.0 — Cidade de 4 quarteirões + guerreiro 8 direções

| Campo | Valor |
| ----- | ----- |
| Versão | **0.1.0** |
| Data | 2026-07-15 |
| Status | **Implementada** (arte ainda placeholder; pipeline OpenAI pronto) |

## 1. Motivação

Estabelecer a **primeira cena jogável** do Jet Village 2: uma cidade top-down legível (4 quarteirões, calçadas, ruas de pedra) e um **guerreiro local** com movimentação e combate animado em **8 direções**.  

O client deve nascer **multiplayer-ready** (estado puro, input como intent), sem implementar netcode nesta versão.

## 2. Escopo

| ID | Entrega |
| -- | ------- |
| **V1** | Mapa data-driven da cidade: grade 2×2 de quarteirões, ruas de pedra (perimetrais + cruz central), calçada contornando cada quarteirão, terreno interno de grama |
| **V2** | Colisão: bordas do mundo bloqueadas; ruas/calçadas/grama andáveis; camada `collision` no JSON |
| **V3** | Guerreiro local: idle + walk em **8 direções** (N/S/L/O + diagonais), teclado WASD/setas |
| **V4** | Animação de **ataque** (one-shot) e **morte** (one-shot); morte impede input |
| **V5** | Contrato **WeaponDef** desacoplado (1 arma starter “espada”); sistemas de movimento/anim não hardcodam skin |
| **V6** | Viewport pixel-perfect (escala inteira, sem suavização); spawn no cruzamento central |
| **V7** | Assets via pipeline OpenAI (`generate-asset`) + atlas JSON mínimo para o sheet do guerreiro |

## 3. Fora de escopo

- Servidor multiplayer, salas, login, outros jogadores visíveis  
- Inventário UI, troca de arma in-game (só contrato no código)  
- Casas interiores, NPCs, quests, chat  
- Corrida (`run`) — pode reusar walk se necessário  
- 3 variantes de ataque por direção (mínimo: **1** clip `attack` por direção)  
- Áudio, dia/noite, PWA  
- Pipeline procedural do Jet Village 1  

## 4. Contratos

### 4.1 Mapa

- Formato inspirado no v1: JSON com `width`, `height`, `tileSize` (**32**), `layers.ground`, `layers.detail` (opcional), `layers.collision`, `spawn`.
- Layout lógico **2×2 quarteirões** + ruas 3–4 tiles + calçada 1 tile.  
- Dimensões exatas (tiles totais) fixadas na arch-spec; ordem de grandeza ~ mundo 50×40 tiles ou menor se FOV exigir.
- Tiles mínimos: **rua pedra** (≥2 variantes), **calçada**, **grama** (≥2 variantes).

### 4.2 Direções

```
up | down | left | right | up-left | up-right | down-left | down-right
```

Facing derivado da velocidade; em diagonal, convenção estável (documentar na arch: preferir eixos consistentes para evitar flicker).

### 4.3 Animação (clips)

| Estado | Loop | Notas |
| ------ | ---- | ----- |
| `idle-{dir}` | sim | 8 dirs |
| `walk-{dir}` | sim | 8 dirs |
| `attack-{dir}` | não (one-shot) | 8 dirs; ao terminar → idle/walk |
| `death-{dir}` | não | 8 dirs ou fallback a 1–4 dirs se sheet limitado; após fim, sem input |

Chaves de clip em inglês kebab; resolução de fallback documentada na arch (ex. `death` genérico).

### 4.4 Input (intent)

Por frame de simulação, o input produz algo equivalente a:

```ts
{ moveX: number; moveY: number; attack: boolean; /* future: interact */ }
```

Sistemas de movimento/combate consomem intent — **não** leem `KeyboardEvent` diretamente (prepara multiplayer).

### 4.5 Arma desacoplada

```ts
interface WeaponDef {
  id: string;
  weaponClass: 'oneHandSword' | string;
  displayName: string; // pt-BR
  poseAtlasId: string;
  poseTextureId: string;
}
```

Player equipa `WeaponDef`; animação usa o pose set da arma.  
**0.1.0:** um único `starter_sword` apontando para o atlas do guerreiro gerado.

### 4.6 Multiplayer (só desenho)

- Simulação local apenas.
- Componentes serializáveis em princípio: posição, direção, estado anim, frame, `weaponId`.
- Netcode **explícito fora** desta versão.

## 5. Arte

| Asset | Kind / método | Notas |
| ----- | ------------- | ----- |
| Sheet guerreiro + espada | `generate-asset` kind `character` | Subject: guerreiro com espada; idle/walk/attack/death; 8 dirs preferencial |
| Tiles rua / calçada / grama | `path` ou prompts dedicados | Cozy top-down; promover a tileset |
| Mapa | JSON versionado (não PNG único da cidade) | Data-driven |

Após gerar: **Read** do PNG; promover para `public/assets/…`.  
Atlas JSON mínimo: `frameSize`, `pivot` (pés), mapa de animações → retângulos ou grid se o sheet permitir.

## 6. Critérios de aceite

1. `npm run dev` mostra cidade 2×2 com ruas de pedra e calçadas legíveis.  
2. Guerreiro spawna no cruzamento central; move em **8 direções** com sprite coerente.  
3. Idle parado; walk em movimento.  
4. Ação de ataque (ex. Space) toca animação de golpe e retorna a idle/walk.  
5. Death (debug key ou stub HP 0) toca animação e bloqueia input.  
6. Trocar `WeaponDef` no registry **não** exige reescrever movement systems.  
7. `architecture:check` verde quando o gate existir; `core` sem imports de `platform`/`game`.  
8. Assets via pipeline OpenAI / promovidos — não editados à mão em `generated/`.  
9. Spec + arch no repo; código EN; UI/docs pt-BR.  
10. `npm run typecheck` e `npm run build` verdes.

## 7. Impacto arquitetural (alto nível)

- Port seletivo `src/core` + `src/platform` do Jet Village 1.  
- `src/game` novo: TileMap, CityScene, player systems, weapons registry.  
- Sem servidor nesta entrega.
