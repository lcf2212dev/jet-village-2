# Spec 0.1.1 — Tiles de chão reais (grama, calçada, pedra)

| Campo | Valor |
| ----- | ----- |
| Versão | **0.1.1** |
| Data | 2026-07-15 |
| Status | **Implementada** |
| Depende de | **0.1.0** (cidade 2×2 + `TileId` + placeholders coloridos) |

## 1. Motivação

A 0.1.0 entregou o mapa e o loop jogável, mas o chão ainda é **retângulos de cor** (`RenderSystem` → `TILE_COLORS`).  
Esta versão troca grama dos quarteirões, calçadas e pedras da rua por **sprites pixel art** gerados no pipeline OpenAI, carregados via tileset e desenhados no jogo — sem mudar o layout lógico da cidade nem o guerreiro.

## 2. Escopo

| ID | Entrega |
| -- | ------- |
| **V1** | Gerar (kind `path`) e revisar os tiles de chão: **grama** (≥2 variantes), **calçada** (≥1), **pedra de rua** (≥2 variantes) |
| **V2** | Promover PNGs revisados para `public/assets/tiles/` + JSON de tileset (`TilesetData`) alinhado aos `TileId` existentes |
| **V3** | Carregar textura + tileset no boot da `CityScene` e **aplicar** no ground: `drawSprite` no lugar de `drawRect` colorido |
| **V4** | Fallback documentado: se textura/tileset ausente, manter cores placeholder (dev/safety) **ou** falhar cedo no load — decisão na arch; preferência: **falhar no load** se o asset promovido for obrigatório |

### Mapeamento mínimo (ids atuais)

| `TileId` | Nome lógico | Arte |
| -------- | ----------- | ---- |
| `StoneA` (0) | Rua pedra A | Variante clara / principal |
| `StoneB` (1) | Rua pedra B | Variante alternada (checker) |
| `Sidewalk` (2) | Calçada | Pedra/lajota mais clara que a rua |
| `GrassA` (3) | Grama A | Verde cozy, tileável |
| `GrassB` (4) | Grama B | Variante sutil (tom/tufts) |

Não é obrigatório criar novos ids; a grade 0.1.0 já pinta esses cinco.

## 3. Fora de escopo

- Sheet / atlas do **guerreiro** (continua placeholder geométrico)  
- Casas, flora decorativa, props de detalhe (`layers.detail`)  
- Autotile / bordas de transição grama↔calçada↔rua (tiles “edge”)  
- Mudança de layout do mapa (tamanhos de quarteirão/rua)  
- Netcode, UI inventário, áudio  
- Pipeline procedural do Jet Village 1  

## 4. Contratos

### 4.1 Arte e geração

- Pipeline: skill **`generate-asset`** → `POST /v1/generate` kind **`path`** (`prompts/path_tile.md`).  
- Subjects em inglês no request; estilo cozy top-down 32×32 legível.  
- Cada geração: **Read** do PNG em `public/assets/generated/path/…` antes de promover.  
- Promoção: copiar revisados para `public/assets/tiles/` (não editar à mão em `generated/`).  
- Aceitável gerar **um sheet** com N tiles (grid) **ou** PNGs separados; o tileset JSON deve apontar `image` + `tileSize` + `columns` + `tileCount` + `names`.

### 4.2 Tileset (`TilesetData`)

Contrato já existente em `src/core/contracts/asset-data.ts`:

```ts
interface TilesetData {
  image: string;       // path relativo ao asset (ex. city-ground.png)
  tileSize: number;    // 32
  columns: number;
  tileCount: number;   // ≥ 5
  names: readonly string[]; // alinhado ao índice = TileId
}
```

- Índice do tile no tileset **=** `TileId` usado em `buildCityMap` / `layers.ground`.  
- Asset id de runtime: reutilizar `ASSET_IDS.cityTileset` (`tileset/city`) e textura associada.

### 4.3 Render

- Ground visível na viewport: para cada célula, `src` rect no tilesheet → `dest` 32×32 mundo.  
- Pixel-perfect: sem suavização (já no renderer).  
- Guerreiro e HUD: sem regressão funcional (podem continuar placeholders).

### 4.4 Multiplayer

Sem impacto: só assets + draw path. Sem netcode.

## 5. Arte (checklist de revisão visual)

| Critério | Esperado |
| -------- | -------- |
| Estilo | Pixel art cozy, top-down ortográfico |
| Tileabilidade | Bordas sem costura óbvia em repetições 2×2 / 4×4 |
| Distinção | Rua ≠ calçada ≠ grama à primeira vista |
| Variantes | Stone A/B e Grass A/B legíveis mas sutis (não “dois biomas”) |
| Proibido | Texto, UI, personagens, watermark, fundo de cena extra |
| Paleta | Quentes/suaves; calçada mais clara; grama verde viva; pedra cinza-azulada ou terrosa |

## 6. Critérios de aceite

1. `npm run dev` mostra a cidade 2×2 com **sprites** de grama, calçada e pedra (não só blocos de cor).  
2. Checker de pedra e variação de grama da 0.1.0 continuam visíveis com as variantes A/B.  
3. Movimento, colisão, spawn e combat do guerreiro **inalterados** em comportamento.  
4. Assets gerados via pipeline OpenAI; promovidos sob `public/assets/tiles/`; tileset JSON versionado.  
5. Cada PNG promovido foi revisado (Read) e atende o checklist da §5.  
6. `npm run typecheck` e `npm run build` verdes; testes de mapa existentes continuam passando.  
7. Spec + arch no repo; código/commits EN; docs de produto pt-BR.  
8. HUD pode atualizar versão exibida para `0.1.1` (cosmético).

## 7. Impacto arquitetural (alto nível)

- **platform:** carregar imagem + registrar textura; opcional helper genérico de load se ainda não existir.  
- **game:** `CityScene.load` registra tileset; `RenderSystem` consulta tileset/texture e `drawSprite`.  
- **core:** contratos `TilesetData` / `Renderer.drawSprite` já existem — preferir reuso.  
- **assets:** novos arquivos em `public/assets/tiles/` (+ gerados intermediários em `generated/path/`).

Detalhamento DAG / ownership → `0.1.1-arch.md` **após** aprovação desta spec.

## 8. Riscos e notas

| Risco | Mitigação |
| ----- | --------- |
| OpenAI gera tile não-tileável / perspectiva errada | Iterar `subject`/`extra`; Read obrigatório antes de promover |
| Sheet com tiles desalinhados do grid 32 | Documentar crop/pack na arch; preferir grid regular no PNG |
| Custo de API | 3–5 gerações focadas (stone sheet, sidewalk, grass sheet) em vez de dezenas |
| Escopo creep para guerreiro | Explicitamente fora; próxima versão se desejado |
