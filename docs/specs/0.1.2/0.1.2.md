# Spec 0.1.2 — Guerreiro completo (8 direções + run/sit)

| Campo | Valor |
| ----- | ----- |
| Versão | **0.1.2** |
| Data | 2026-07-15 |
| Status | **Implementada** |
| Depende de | **0.1.1** (cidade com tiles de chão reais; guerreiro ainda placeholder geométrico) |

> **Nota:** branches/worktrees antigos `0.1.2-warrior-sheet` e `0.1.3-warrior-full` são **ignorados**. Esta é a versão canônica do sheet do guerreiro a partir de `develop`.

## 1. Motivação

A 0.1.0/0.1.1 entregam cidade jogável, mas o personagem ainda é um **placeholder geométrico**.  
Esta versão gera e integra o **guerreiro real** (pixel art cozy, pipeline OpenAI), com o conjunto completo de animações pedido para movimento e combate local em **8 direções**.

## 2. Escopo

| ID | Entrega |
| -- | ------- |
| **V1** | Gerar sheet(s) do guerreiro via `generate-asset` (kind `character`), com **fundo transparente** explícito no prompt |
| **V2** | Clips por estado × direção: **walk**, **run**, **attack**, **sit**, **death** — cada um em **8 direções** |
| **V3** | Manter **idle** (já no client 0.1.0) em 8 direções — parado sem sit; necessário para o loop atual |
| **V4** | Atlas JSON (`SpriteAtlasData`) + PNG promovido em `public/assets/sprites/`; carregar no boot da `CityScene` |
| **V5** | Render do player via `drawSprite` + atlas (placeholder só como fallback se load falhar) |
| **V6** | Input + estados: **run** (modificador de movimento) e **sit** (toggle/hold — decisão na arch); attack/death como one-shot |
| **V7** | Velocidade de movimento maior em `run`; em `sit` e `death` bloquear movimento (e attack conforme prioridade) |

### 2.1 Direções (obrigatórias em todos os clips acima)

```
up | down | left | right | up-left | up-right | down-left | down-right
```

Equivalentes de produto: norte, sul, oeste, leste, noroeste, nordeste, sudoeste, sudeste.

### 2.2 Matriz de clips

| Estado | Loop | Direções | Notas |
| ------ | ---- | -------- | ----- |
| `idle-{dir}` | sim | 8 | Parado em pé (respiração sutil) |
| `walk-{dir}` | sim | 8 | Movimento normal |
| `run-{dir}` | sim | 8 | Movimento rápido; corpo com mais momentum |
| `attack-{dir}` | não (one-shot) | 8 | Golpe com espada; ao terminar → idle/walk/run |
| `sit-{dir}` | sim | 8 | Sentado olhando na direção; sem deslocamento |
| `death-{dir}` | não (one-shot) | 8 | Após fim, sem input |

Chaves de clip em inglês kebab (como 0.1.0).  
Contagem mínima de frames (orientação de arte; atlas documenta o real):

| Estado | Frames/dir (meta) |
| ------ | ----------------- |
| idle | 2–4 |
| walk | 4–8 |
| run | 4–8 |
| attack | 4–8 |
| sit | 2–4 |
| death | 4–8 |

## 4. Contratos

### 4.1 Arte e geração

- Pipeline: skill **`generate-asset`** → kind **`character`** (`prompts/character_sheet.md`).  
- **Fundo transparente obrigatório** (já no template; reforçar em `extra`/subject se necessário).  
- Sem texto, labels, grid lines, watermark, cenário de fundo.  
- Guerreiro **humanoide com espada** (starter), top-down / ¾, cozy pixel art, silhueta legível em ~32–64 px por frame.  
- Uma ou mais gerações: se um único sheet 8 dirs × 6 estados for inviável na IA, **dividir por estado** (ex. `warrior-walk`, `warrior-run`, …) e unificar no atlas — decisão na arch; aceitável desde que o runtime veja um (ou N) atlas coerente.  
- Após gerar: **Read** do PNG; só promover se silhueta, dirs e fundo ok.

### 4.2 Atlas

- Formato `SpriteAtlasData` (pode estender na arch se precisar de `startFrame` / multi-image).  
- Pivot nos **pés**.  
- Toda chave `estado-direção` listada na matriz §2.2 deve resolver (sem depender de mirror em runtime, salvo documentado como fallback L/R).  
- Fallback de resolução de clip: documentar na arch (ex. diagonal → eixo cardinal; ausência de sit → idle).

### 4.3 Input (intent) — evolução multiplayer-ready

Estender o intent atual (não ler teclado nos sistemas de animação):

```ts
{
  moveX: number;
  moveY: number;
  attack: boolean;
  run: boolean;   // novo — ex. Shift
  sit: boolean;   // novo — ex. C (toggle ou hold; arch define)
  /* kill debug permanece se útil */
}
```

Prioridade sugerida de estados (arch pode refinar):

1. `death` (trava tudo)  
2. `attack` (one-shot; interrompe walk/run/sit)  
3. `sit` (bloqueia move; attack pode levantar e golpear — preferência: **sim**, attack cancela sit)  
4. `run` se movendo + run pressed  
5. `walk` se movendo  
6. `idle` parado  

### 4.4 Movimento

- `WALK_SPEED` existente (~96 px/s).  
- `RUN_SPEED` maior (ex. 1.6× walk — valor na arch).  
- Em `sit` / `death` / durante `attack`: sem deslocamento (como attack/death na 0.1.0).

### 4.5 Arma

- Continua `WeaponDef` + `starter_sword` apontando para o atlas/textura do guerreiro.  
- Não hardcodar skin nos sistemas de movimento.

### 4.6 Multiplayer (só desenho)

- Simulação local.  
- Serializável em princípio: posição, direção, `animState` (incl. run/sit), frame, `weaponId`.  
- Netcode **fora** desta versão.

## 6. Critérios de aceite

1. `npm run dev`: guerreiro **sprite** (não só placeholder) na cidade 0.1.1.  
2. Movimento em **8 direções** com clip `walk-{dir}` coerente.  
3. Com modificador de corrida: clip `run-{dir}` e velocidade maior.  
4. Parado: `idle-{dir}`; ação sit: `sit-{dir}` e sem movimento.  
5. Space (ou binding atual): `attack-{dir}` one-shot e retorno a idle/walk/run.  
6. Death (debug K ou HP 0): `death-{dir}`, bloqueia input após/during.  
7. Atlas + PNG em `public/assets/sprites/` (promovidos); gerados via pipeline, não editados à mão em `generated/`.  
8. `core` sem imports de `game`/`platform`; gates `typecheck` + `build` (+ `test` / `architecture:check` se existirem) verdes.  
9. Spec (+ arch após aceite) no repo; código/commits EN; docs de produto pt-BR.  
10. Cidade/tiles 0.1.1 sem regressão funcional.

## 7. Impacto arquitetural (alto nível)

- **game:** `AnimState` + `PlayerIntent` + `GameAction` para run/sit; `AnimationStateSystem`, `MovementSystem`, `AnimationPlaybackSystem`, `RenderSystem`, `PlayerInputSystem`, keymap.  
- **core/platform:** possível extensão mínima de `GameAction` / input; atlas se o contrato JSON precisar de campos extras.  
- **assets:** sheet(s) + JSON do guerreiro.  
- Sem servidor.

## 8. Riscos

| Risco | Mitigação |
| ----- | --------- |
| Sheet único 8×6 estados inviável na IA | Gerar por estado (ou por grupo); atlas multi-strip; re-gerar |
| Diagonais ruins | Fallback cardinal; regenerar dirs problemáticas |
| Fundo opaco residual | Prompt reforça transparent; validar Read/alpha; re-gerar |
| Sit vs idle confusos | Frames de sit com pose sentada clara; input dedicado |
| Custo de API | Poucas gerações focadas + promote só do que passar no Read |
